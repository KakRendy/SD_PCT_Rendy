MODUL 01 // FONDASI STRUKTUR DATA

Linear vs Non-Linear

DASAR

Struktur Data adalah cara menyimpan, mengatur, dan mengelola data di dalam memori komputer agar dapat diakses, dicari, dan dimodifikasi secara efisien. Pemilihan struktur data yang tepat sangat menentukan apakah sebuah aplikasi berjalan dalam hitungan milidetik atau mengalami bottleneck saat menangani jutaan data.

2. Struktur Data Non-Linear (Hierarkis / Jaringan)

Data terhubung dalam hierarki / graf jaringan
Tree (Pohon) ★ FOKUS UTAMA

Struktur hierarki yang dimulai dari satu akar (root) dan memiliki cabang-cabang ke node di bawahnya (child/leaf). Sangat efisien untuk pencarian data terstruktur, contohnya Binary Search Tree (BST).

Graph (Graf) ➔ Vertex & Edge

Kumpulan titik (vertex/node) yang dihubungkan oleh garis (edge). Digunakan untuk merepresentasikan hubungan kompleks, seperti rute Google Maps, topologi jaringan komputer, atau relasi mutual friends di media sosial.

Hash Table ➔ O(1) Lookup

Menyimpan data dalam format pasangan kunci-nilai (key-value). Menggunakan fungsi matematika khusus (hash function) untuk menempatkan data, sehingga proses pencarian (lookup) bisa dilakukan dengan sangat cepat.

ROOT (Node 50): Simpul paling atas dari pohon. Satu-satunya node yang tidak memiliki induk (Parent).
⚡ Hukum Wajib Binary Search Tree (BST Property)

Sebuah Binary Tree disebut Binary Search Tree (BST) jika dan hanya jika untuk setiap node $N$:

1. ATURAN CABANG KIRI (LEFT)

Seluruh nilai node pada Sub-tree Kiri wajib LEBIH KECIL ($<$) daripada nilai Parent-nya.

2. ATURAN CABANG KANAN (RIGHT)

Seluruh nilai node pada Sub-tree Kanan wajib LEBIH BESAR ($>$) daripada nilai Parent-nya.

Mengapa BST Penting Dipelajari?

Pada Array tak terurut, mencari 1 data di antara $1.000.000$ elemen butuh hingga $1.000.000$ pengecekan ($O(n)$). Dengan BST yang seimbang, setiap langkah membelah ruang pencarian menjadi separuhnya! Mencari di antara $1.000.000$ data hanya butuh maksimal $\approx 20$ langkah perbandingan ($\log_2(10^6) \approx 19.93$).

Di Mana & Kapan BST Dibutuhkan?

Gunakan BST ketika data Anda sering berubah secara dinamis (sering ada penambahan & penghapusan data baru) namun Anda tetap membutuhkan pencarian cepat serta kemampuan menampilkan data secara terurut otomatis atau pencarian rentang nilai (Range Query, misal: cari produk harga Rp 50rb–100rb).

MODUL 03 // MEKANISME & ANALISIS

Cara Kerja Algoritma & Use Cases

ALGORITMA
1. Operasi INSERT (Menambah Simpul)

Mulai dari Root. Bandingkan nilai baru dengan node saat ini: jika lebih kecil belok ke kiri, jika lebih besar belok ke kanan. Ulangi secara rekursif hingga menemukan posisi kosong (NULL), lalu pasang node baru tersebut sebagai Leaf.

2. Operasi SEARCH (Mencari Simpul)

Mulai dari Root. Jika nilai target sama dengan node saat ini, pencarian berhasil! Jika target lebih kecil, telusuri sub-tree kiri (abaikan seluruh sub-tree kanan). Jika lebih besar, telusuri sub-tree kanan.

3. Operasi DELETE (Menghapus Simpul — 3 Kasus Penting)
  • Kasus 1 (Leaf Node / Tanpa Anak): Langsung hapus node tersebut dari parent-nya.
  • Kasus 2 (Memiliki 1 Anak): Hubungkan parent dari node yang dihapus langsung ke satu-satunya anak milik node tersebut.
  • Kasus 3 (Memiliki 2 Anak): Cari In-Order Successor (nilai terkecil pada sub-tree kanan), salin nilainya ke node yang akan dihapus, lalu hapus node penerus tersebut.
4. Operasi TRAVERSAL (Penelusuran Seluruh Pohon)
In-Order (L-Root-R)
Menghasilkan urutan angka Ascending (Terkecil ke Terbesar)!
Pre-Order (Root-L-R)
Berguna untuk menyalin (clone) atau serialisasi struktur pohon.
Post-Order (L-R-Root)
Berguna saat menghapus seluruh pohon dari daun hingga ke akar.

✓ Kelebihan (Strengths)

  • • Efisiensi Tinggi: Search, Insert, dan Delete rata-rata berjalan dalam waktu $O(\log n)$.
  • • Selalu Terurut: Tidak perlu sorting ulang; cukup lakukan In-Order Traversal untuk mendapatkan data berurutan.
  • • Ukuran Dinamis: Tidak perlu alokasi blok memori statis seperti Array.

⚠ Kekurangan (Weaknesses)

  • • Risiko Skewed Tree (Pohon Miring): Jika data dimasukkan secara berurutan (misal: 10, 20, 30, 40), BST akan merosot menjadi garis lurus seperti Linked List dengan performa buruk $O(n)$.
  • • Overhead Memori Pointer: Setiap node wajib menyimpan 2 pointer ekstra (Left & Right).
  • • Butuh Penyeimbang (Self-Balancing): Pada sistem produksi digunakan varian seperti AVL Tree atau Red-Black Tree.

class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

class BinarySearchTree:
    def __init__(self):
        self.root = None

    def insert(self, root, key):
        # Jika sub-tree kosong, buat Node baru sebagai Leaf
        if root is None:
            return Node(key)
        # Hukum BST: Kiri < Parent < Kanan
        if key < root.key:
            root.left = self.insert(root.left, key)
        elif key > root.key:
            root.right = self.insert(root.right, key)
        return root

    def search(self, root, target):
        # Basis: Root kosong atau target ditemukan
        if root is None or root.key == target:
            return root
        if target < root.key:
            return self.search(root.left, target)
        return self.search(root.right, target)

    def inorder_traversal(self, root, result=None):
        if result is None: result = []
        if root:
            self.inorder_traversal(root.left, result)   # 1. Kiri
            result.append(root.key)                     # 2. Root
            self.inorder_traversal(root.right, result)  # 3. Kanan
        return result  # Menghasilkan data terurut!
class TreeNode {
    constructor(value) {
        this.value = value;
        this.left = null;
        this.right = null;
    }
}

class BinarySearchTree {
    constructor() { this.root = null; }

    insert(value) {
        const newNode = new TreeNode(value);
        if (!this.root) { this.root = newNode; return this; }
        let curr = this.root;
        while (true) {
            if (value === curr.value) return undefined; // Tolak duplikat
            if (value < curr.value) {
                if (!curr.left) { curr.left = newNode; return this; }
                curr = curr.left;
            } else {
                if (!curr.right) { curr.right = newNode; return this; }
                curr = curr.right;
            }
        }
    }

    find(target) {
        let curr = this.root;
        while (curr) {
            if (target === curr.value) return curr;
            curr = target < curr.value ? curr.left : curr.right;
        }
        return null;
    }
}
